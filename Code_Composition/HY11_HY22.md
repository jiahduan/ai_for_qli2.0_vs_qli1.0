# Code Composition — HY11/HY22

## 对比总览

| 维度 | QLI1.0 | QLI2.0 |
|---|---|---|
| 关键字命中 | 多处一致证据 | 全树零匹配 |
| 脚本证据 | `release/populate_prebuilt.sh -v HY11/HY22`(CRM variant参数) | 不适用 |
| 清单文件 | 各专有模块下`crm/noship_common_HY11/HY22`(security/display/kernel等release目录) | 不适用 |
| manifest属性 | `x-ship="hy11,hy22"`、`x-quic-distributable package="hy11,grease,hy22"` | 不适用 |
| 功能定位 | CRM(Configuration/Component Release Management)变体标识,按变体/客户/批次分发预编译产物 | 无对应机制 |

## 关键差异

- HY11/HY22是QLI1.0专有的CRM变体分发机制,把闭源组件(securemsm/camera/display/fastcv)预编译产物按变体打进`prebuilt_HY11`/`prebuilt_HY22`。
- QLI2.0全无此机制,与Layer_Architecture.md、Patch_Management.md的整体趋势一致:大幅去除闭源专有组件配套的私有分发基础设施。

## 待确认

- "HY"全称及HY11/HY22具体业务差异(客户/许可/ABI差异),需向QLI1.0 release/CRM团队owner确认。
- QLI2.0是否有更名后的等价"预编译产物变体分发"机制,避免误判为能力缺失。
