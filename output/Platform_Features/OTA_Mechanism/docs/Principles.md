# OTA_Mechanism 原理文档

本文档解释"OTA机制"在设备全生命周期里管什么范围、为什么"镶像完整性校验的消失"是P0级风险而不是一般的架构选型差异——这是理解`OTA_Mechanism.md`Comparison结论的前置知识,不涉及QLI1.0/QLI2.0具体差异结论(结论见`../OTA_Mechanism.md`)。

## 1. OTA_Mechanism管的是什么

OTA(Over-The-Air)管的是"设备出厂后如何进行软件更新":升级包如何生成/分发、更新如何应用(整包/差分/A-B切换/文件系统级commit)、更新失败如何回滚、以及服务端信任模型(谁签名、怎么验证)。它是设备生命周期里**唯一被设计为允许远程改写系统的合法通道**,因此这条通道本身的可信程度,直接决定整机的安全基线。

## 2. 为什么这个主题要讲清楚,以及为什么完整性校验消失是P0

OTA链条里有两个容易被混为一谈、但实际互不可替代的环节:

- **签名校验**(如Uptane/TUF的Director/Image Repo签名):验证的是"这个升级包/commit是不是官方发出的、没有在传输过程中被篡改"——这是对**下载内容**的信任判断,发生在更新发生的那一刻。
- **运行时镶像完整性校验**(dm-verity/AVB):验证的是"设备磁盘上现在实际运行的rootfs内容,是不是当初写入/升级时的那个内容,没有被后续任何手段(如本地提权、物理接触篡改)篡改过"——这是对**磁盘上持久内容**的信任判断,发生在设备运行的每一次挂载/读取时。

两者解决的是不同时间点、不同攻击面的问题:签名校验管"进来的东西干不干净",完整性校验管"已经在磁盘上的东西有没有被动过"。QLI1.0用一整套dm-verity/AVB bbclass机制覆盖了后一道防线;QLI2.0的量产镜像里,即使meta-security层客观存在等价能力,也没有任何qcom镜像recipe真正引用它——这意味着这道防线从"存在"变成"事实上不存在",而不是"换了个等价实现"。这正是判定P0(而非P1/P2)的原理依据:影响范围广(所有走qcom-distro/qcom-distro-sota的量产镜像)、且不可逆(rootfs完整性目前没有任何运行时校验兜底,只能依赖aktualizr在拉取/部署阶段的一次性Uptane签名校验),同时这类"能力人在场但没上岗"的风险天然容易被误判为"已有等价能力可用"从而被忽视——三者叠加,才够得上P0而不是普通的架构选型差异。

## 3. 与相邻主题的分工边界原理

OTA机制的完整结论依赖多个相邻主题各自的证据,但每个相邻主题只负责讲清楚自己那一部分的完整故事,本主题只引用其结论作为交叉验证的独立证据源:

- **首次刷机工具链与流程本身**归[Flash_Process](../Flash_Process.md)——原理:首刷解决"从0到1"的问题,发生在产线;OTA解决"从1到N"的问题,发生在设备已经在跑之后。OSTree只改变第二次及后续升级的路径,不改变首刷方式,这也是为什么本主题在《对比范围》里专门确认"与首刷流程的边界"而不是默认两者无关。
- **分区结构本身**(单一rootfs vs Android式A/B分区)归[Partition_Layout](../../Boot_Architecture/Partition_Layout/Partition_Layout.md)——分区怎么划分是静态设计,OTA只是"利用"这个设计做升级/回滚,不是分区设计本身。
- **cmdline层面verity参数消失的证据细节**归[Bootargs](../../Boot_Architecture/Bootargs/Bootargs.md)——cmdline参数是内核启动时读取的具体证据点之一,本主题引用其结论作为P0判断的一个独立证据源,但不重复展开该证据本身是怎么取得的。
- **QLI1.0三个systemd补丁去向的完整追踪过程**归[Patch_Management](../../Code_Composition/Patch_Management/Patch_Management.md)——补丁追踪本身是Patch_Management主题方法论的应用案例,本主题只借用其追踪结果(`fstab-generator-Honor-verity-enabled-cmdline.patch`在QLI2.0没有对应物)作为佐证。

判断原则:**"设备已经在跑之后,更新与信任链怎么设计"归本主题;首刷、分区设计、cmdline证据本身、补丁追踪过程各自的完整故事归对应专题**。本主题的独特价值在于把这些分散在不同主题里的证据点串起来,交叉验证出一个任何单一证据源都不足以支撑的结论——完整性校验机制的整体缺失。
